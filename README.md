# staging/board

A small shared board showing who is currently using which server. Built to run on
plain shared hosting — **PHP + a JSON file, no database server required.**

- React (Vite + Tailwind) frontend
- PHP API, no framework, no Composer
- State lives in one JSON file guarded by `flock()` + atomic `rename()`
- One shared team password gates the whole board

---

## How state stays correct without a database

Two people clicking **Claim** in the same second is the only real concurrency
problem this app has. It is solved by two things working together:

1. **An exclusive `flock()`** held across the entire read-modify-write cycle, so
   the two requests are serialised rather than racing.
2. **Write-to-temp then `rename()`**, which is atomic on Linux. A reader always
   sees either the complete old file or the complete new one — never a half-written
   one — so the 5-second polling reads need no lock at all.

On top of that, the API is state-checked: the **Claim** button sends
`expect: "available"`. If someone else grabbed the server in the meantime, the
server responds `409`, returns the fresh board, and the UI tells you who beat you
to it instead of silently stealing it.

## Local development

Requires Node 18+ and PHP 8.x on your PATH.

```bash
npm install
cp api/config.example.php api/config.php
php tools/hash-password.php 'pick-a-dev-password'
```

Paste that hash into `api/config.php` as `TEAM_PASSWORD_HASH`, then point
`DATA_DIR` somewhere local, e.g.:

```php
const DATA_DIR = __DIR__ . '/../serverboard-data';
```

Run the two servers in separate terminals:

```bash
npm run dev:api
```

```bash
npm run dev
```

Open the Vite URL (usually `http://localhost:5173`). Vite proxies `/api` to the
PHP server, which keeps everything same-origin so the session cookie behaves
exactly as it will in production.

## Deploying to idCloudHost (cPanel shared hosting)

### 1. Build

```bash
npm run build
```

This produces `dist/` — the static frontend plus the `.htaccess` from `public/`.

### 2. Create the data directory **outside** `public_html`

In cPanel File Manager, at the same level as `public_html` (i.e. in your home
directory), create:

```
serverboard-data
```

Set its permissions to **0750** (or 0770 if PHP runs as a different user). This
placement is what stops anyone fetching your data over HTTP.

### 3. Upload

| Local | Server |
|---|---|
| everything inside `dist/` | `public_html/` |
| everything inside `api/` | `public_html/api/` |

Do **not** upload `node_modules/`, `src/`, or `config.example.php` — only the
built output and the API.

### 4. Configure

Create `public_html/api/config.php` (copy `config.example.php` and edit). Set:

- `SERVERS` — your server list; this is the single source of truth, the frontend
  renders whatever the API returns
- `TEAM_PASSWORD_HASH` — generated by `php tools/hash-password.php 'your-password'`
- `DATA_DIR` — the default `__DIR__ . '/../../serverboard-data'` resolves to
  `/home/USER/serverboard-data`, which is correct for a standard cPanel layout

### 5. Turn on HTTPS

Enable the free SSL certificate in cPanel and force HTTPS. The session cookie is
marked `Secure` automatically once the site is served over HTTPS.

### 6. Check it

Visit your domain. You should get the sign-in screen. If you instead see
`{"error":"Server not configured..."}`, `config.php` is missing. If you see a
data-directory error, the path in `DATA_DIR` is wrong or not writable.

## Adding or removing a server

Edit `SERVERS` in `public_html/api/config.php`. Nothing else needs to change —
no rebuild, no frontend edit, no touching the JSON file. New servers appear as
`available`; removed ones disappear on the next poll.

## Notes and limits

- **Sign-in is one shared password.** Names are labels, not accounts. It keeps
  strangers off a public URL; it is not real per-user authentication.
- **Signing out does not release your servers.** Leaving for the day shouldn't
  quietly mark a server free while it's still busy.
- **Only the holder can Release.** Anyone else has to Take over, which is logged
  as such — so a hold never disappears without a name attached.
- **The activity log keeps the last 25 entries** (`LOG_LIMIT` in config).
- **Polling is every 5 seconds** and pauses while the browser tab is hidden.
- **Identity is server-side.** The name is read from the session, not from the
  request body, so log entries can't be forged by editing a request.

### If you outgrow the JSON file

Moving to MySQL touches only `board_read()`, `board_write()` and `board_mutate()`
in `api/_bootstrap.php`. Everything else — the endpoints, the frontend — is
unchanged. That's the point at which you'd want it: usage history, reporting, or
many more servers than a screenful.
